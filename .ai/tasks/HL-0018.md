# HL-0018 — Diseñar estructura de persistencia para servicios de plataforma

- **ID:** HL-0018
- **Objetivo:** Definir el layout de subdirectorios bajo `/srv/homelab/app_data/` para los componentes de plataforma central.
- **Descripción:** Establecer la jerarquía de directorios, permisos y propiedad para Caddy y futuros servicios de plataforma. Garantizar que el diseño sea extensible para PostgreSQL, Redis y servicios de aplicación sin romper la convención existente.
- **Dependencias:** Sprint 0.B, ADR-001, HL-0016.
- **Estado:** Completed
- **Responsable:** AI Agent
- **Sprint:** Sprint 2.A
- **Fase:** A — Diseño
- **ADR:** ADR-001

## Checklist

- [x] Definir layout de `/srv/homelab/app_data/caddy/` (data, config).
- [x] Documentar permisos y propiedad de cada directorio.
- [x] Definir convención de nombres para servicios futuros (`app_data/<servicio>/`).
- [x] Verificar compatibilidad con la estructura existente del bootstrap.
- [x] Establecer criterios de validación (`ls`, `stat`).

## Notas

La convención de persistencia es: `/srv/homelab/app_data/<nombre_servicio>/`. Cada servicio es responsable de sus subdirectorios internos. Los permisos por defecto son `755:root:root`, salvo que el servicio requiera algo distinto (documentado en su compose).
