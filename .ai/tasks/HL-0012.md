# HL-0012 — Definir criterios de aceptación y evidencias del Bootstrap

- **ID:** HL-0012
- **Objetivo:** Establecer los criterios de aceptación verificables y las evidencias exactas que Sprint 1.B deberá recopilar para dar el Bootstrap por completado.
- **Descripción:** Documentar la tabla de validaciones (qué comando ejecutar, qué salida se espera) y los criterios que determinan si el Bootstrap fue exitoso o fallido. Incluir también el contrato de documentación: qué debe contener `docs/BOOTSTRAP.md`.
- **Dependencias:** HL-0009, HL-0010, HL-0011.
- **Estado:** Planned
- **Responsable:** Unassigned
- **Sprint:** Sprint 1.A
- **Fase:** Phase 1 — Bootstrap
- **ADR:** ADR-001, ADR-002, ADR-003

## Checklist

- [ ] Definir la tabla completa de validaciones con comando y salida esperada.
- [ ] Definir el criterio de idempotencia: el script debe poder ejecutarse dos veces sin errores.
- [ ] Definir el contenido mínimo de `docs/BOOTSTRAP.md` (guía de uso, prerrequisitos, qué instala, cómo verificar).
- [ ] Definir el contenido mínimo del log de ejecución `~/homelab-bootstrap.log`.
- [ ] Especificar que las evidencias se capturarán como sección `## Evidence` en esta tarea una vez Sprint 1.B ejecute.

## Notas

La distinción entre "criterio de aceptación" y "evidencia" es importante en el EOS:
- **Criterio de aceptación:** la condición que debe cumplirse (ej. "Docker CE ≥ 24.0 debe estar instalado").
- **Evidencia:** la prueba documentada de que se cumplió (ej. la salida de `docker --version` pegada en el archivo de tarea).

Sprint 1.B no puede darse por cerrado sin las evidencias reales del host `homelab` capturadas en este archivo.
